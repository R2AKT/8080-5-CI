1. Обзор программы

i8080-5 CI (i8080-5 Control Interface) — комплексная среда для работы с процессором Intel 8080 и устройствами на его базе. Программа объединяет:

  • Эмулятор i8080 — полная эмуляция процессора со всеми 256 инструкциями, включая недокументированные
  • Отладчик — breakpoints (обычные и условные), пошаговое выполнение, watch-окна, трассировка
  • Hex-редактор — просмотр и редактирование образа памяти
  • Дизассемблер — со стрелками переходов, подсветкой типов команд
  • Работа с реальным устройством — чтение/запись памяти и IO-портов по COM-порту (протокол SLIP)
  • Тест памяти — тестирование RAM устройства различными паттернами
  • IO Секвенсор — выполнение последовательности операций ввода-вывода
  • Сравнение — сравнение текущего образа памяти с файлом
  • Скрипты — автоматизация через Python-скрипты
  • MCP-сервер — интеграция с AI-ассистентами

Программа поддерживает русский и английский языки интерфейса и светлую/тёмную темы.

2. Установка и запуск

2.1. Требования

  • Python 3.10+
  • PySide6
  • pyserial
  • Для MCP: mcp, uvicorn, starlette, pydantic, pydantic-settings

2.2. Установка зависимостей

pip install PySide6 pyserial
pip install mcp uvicorn starlette pydantic pydantic-settings

2.3. Запуск

python i8080_CI.py

Программа запускается с окном 1280×720. Язык и тема определяются автоматически из системных настроек (можно изменить в интерфейсе).

4. Вкладка «Управление»

4.1. Подключение к устройству

  1. Выберите COM-порт из выпадающего списка
  2. Выберите скорость (9600, 38400, 57600, 115200)
  3. Нажмите «Подключиться»
  4. Программа отправит NOP для проверки соединения

💡 Если устройство не обнаружено, нажмите «Обновить» для обновления списка портов.

4.2. Управление шиной

Для работы с памятью и IO устройства необходимо захватить шину:

  • «Захватить шину (HOLD)» — отправляет сигнал HOLD процессору. Программа ожидает подтверждения HLDA.
  • «Освободить шину (UnHOLD)» — освобождает шину, процессор продолжает работу.

⚠️ Важно: перед чтением/записью памяти устройства необходимо захватить шину. При закрытии программы шина освобождается автоматически.

4.3. Файлы

  • «Сохранить дамп (.hex)» — сохранение текущего образа памяти в Intel HEX или BIN формат
  • «Загрузить прошивку (.hex/.bin)» — загрузка прошивки в локальный образ памяти. Для BIN-файлов запрашивается базовый адрес. После загрузки предлагается записать прошивку в устройство (если подключено и шина захвачена).

4.4. MCP-сервер

Кнопка «MCP Server: OFF/ON» включает/выключает встроенный MCP-сервер для интеграции с AI-ассистентами. Подробнее — в разделе MCP-интеграция.

5. Вкладка «Данные»

Позволяет читать и записывать значения в память и IO-порты устройства.

5.1. Память (RAM/ROM)

  • Адрес (HEX) — адрес в памяти (4 hex-цифры)
  • Разрядность (бит) — 8, 16, 24, 32 бита
  • Значение (HEX) — значение для записи
  • Порядок байтов — Little-endian или Big-endian
  • Кнопки «Прочитать» и «Записать»

5.2. IO-порты

Аналогично памяти, но адрес — это номер порта (2 hex-цифры).

⚠️ Для работы с памятью и IO устройства необходимо подключение и захват шины.

6. Вкладка «Hex Редактор»

6.1. Обзор

Hex-редактор отображает образ памяти в виде таблицы:

  • Колонка 0 — адрес строки
  • Колонки 1-16 — байты (00-F)
  • Колонка 17 — ASCII-представление

6.2. Возможности

  • Редактирование — двойной клик по ячейке для редактирования значения
  • Подсказки — при наведении на байт показывается мнемоника соответствующей инструкции
  • Undo/Redo — Ctrl+Z / Ctrl+Y (до 100 операций)
  • Контекстное меню (правый клик):
    • Копировать адрес
    • Копировать значение
    • Инвертировать байт
    • Заполнить диапазон
    • Дизассемблировать отсюда
    • Перейти к адресу
  • Поиск — Ctrl+F (HEX-паттерн, ASCII-строка, HEX с маской ??)
  • Переход к адресу — Ctrl+G
  • Чтение блока — чтение блока из устройства в образ

6.3. Диапазон

В верхней части отображается текущий диапазон памяти и количество байт.

7. Вкладка «Дизассемблер»

7.1. Обзор

Дизассемблер отображает дизассемблированный код со следующими возможностями:

  • Стрелки переходов — цветные стрелки показывают цели переходов (JMP, CALL, Jcc, Ccc, RST)
  • Цветовая подсветка типов команд:
    • 🔵 Синий — переходы (JMP, CALL, Jcc, Ccc, RST)
    • 🟢 Зелёный — операции с памятью (LDA, STA, LHLD, SHLD, LDAX, STAX, XCHG, XTHL)
    • 🟣 Фиолетовый — ввод-вывод (IN, OUT)
    • ⚪ Серый — управление (NOP, HLT, DI, EI, RET, PCHL, SPHL)
    • 🟠 Оранжевый — регистры и данные (MVI, LXI, INR, DCR, MOV, INX, DCX)
    • 🟡 Жёлтый — арифметика и логика (ADD, ADC, SUB, SBB, ANA, XRA, ORA, CMP и др.)
    • 🟢 Бирюзовый — стек (PUSH, POP)
    • 🔴 Красный — недокументированные команды (NOP*, RET*, CALL*)
  • Комментарии переходов — ; -> XXXXh показывает цель перехода

7.2. Управление

  • Start — начальный адрес дизассемблирования
  • Len — длина (количество байт)
  • «Дизассемблировать» — выполнить дизассемблирование
  • Авто при чтении/загрузке — автоматическое дизассемблирование при чтении из устройства или загрузке файла
  • «Экспорт» — экспорт дизассемблированного листинга в файл (.asm / .txt)

7.3. Изменение размера шрифта

Ctrl + колесо мыши — изменение размера шрифта дизассемблера.

8. Вкладка «Тест Памяти»

Позволяет тестировать RAM устройства различными паттернами.

Параметры

  • Start — начальный адрес (HEX)
  • End — конечный адрес (HEX)
  • Паттерн — выбор паттерна:
    • Checker — шахматный паттерн (55/AA)
    • Zero — все нули
    • One — все FF
    • Addr — значение равно адресу

Запуск

Нажмите «Запустить тест памяти». Прогресс отображается в прогресс-баре. Ошибки записываются в журнал с указанием адреса, ожидаемого и полученного значений.

⚠️ Тест памяти перезаписывает содержимое RAM. Не запускайте тест на области с важными данными.

9. Вкладка «IO Секвенсор»

9.1. Одиночные операции IO

  • Порт (HEX) — номер порта
  • Значение (HEX) — значение
  • Кнопки «Читать (IN)» и «Записать (OUT)»

9.2. Последовательности

Позволяет выполнять последовательность операций ввода-вывода.

Формат последовательности:

W 01 FF ; Запись в порт 01h значения FFh
R 02 ; Чтение из порта 02h
D 10 ; Задержка 10 мс
  • W PP DD — запись в порт PP значения DD
  • R PP — чтение из порта PP
  • D NN — задержка NN миллисекунд
  • Строки, начинающиеся с ; или # — комментарии

Управление

  • «Загрузить файл...» — загрузка последовательности из файла
  • «Выполнить последовательность» — выполнение последовательности

10. Вкладка «Сравнение»

Позволяет сравнить текущий образ памяти с файлом.

Использование

  1. «Загрузить файл для сравнения» — загрузка файла (.hex / .bin)
  2. «Сравнить» — выполнение сравнения
  3. «Экспорт отчёта» — экспорт результатов в файл (.txt / .csv)

Результаты

Таблица отображает различия:

  • Адрес — адрес различия
  • Текущий — текущее значение
  • Файл — значение из файла
  • Статус — тип различия:
    • 🟡 Изменено — значение отличается
    • 🟢 Добавлено в файле — есть в файле, отсутствует в текущем образе
    • 🔴 Удалено в файле — есть в текущем образе, отсутствует в файле

12. Вкладка «Эмулятор»

Полноценный отладчик процессора i8080. Вкладка разделена на 4 колонки:

12.1. Колонка 1: Дизассемблированный код

Отображает дизассемблированный код с:

  • ► — текущая позиция PC (жёлтая подсветка)
  • ● — точки останова (красный — обычная, оранжевый — условная)
  • ▷ — курсор Run to Cursor (зелёный)
  • Стрелки переходов

Взаимодействие с кодом:

  • Одинарный клик — установка курсора Run to Cursor
  • Двойной клик — установка/удаление точки останова
  • Контекстное меню (правый клик):
    • ▶ Run to Cursor (Ctrl+F10)
    • ⤳ Run from Here
    • ⇢ Jump to Cursor
    • ● Toggle Breakpoint
    • ◉ Set Conditional BP...

12.2. Колонка 2: Watch

Watch-окно для наблюдения за значениями памяти и регистров.

Типы наблюдения:

  • Память (байт) — наблюдение за байтом памяти
  • Память (слово) — наблюдение за словом (2 байта)
  • Регистр — наблюдение за регистром (A, B, C, D, E, H, L, BC, DE, HL, SP, PC, FLAGS)

Форматы отображения: hex, dec, signed, bin, ascii

Возможности:

  • Добавление элементов наблюдения
  • Удаление элементов
  • Очистка всех элементов
  • Сохранение/загрузка пресетов (JSON)
  • Подсветка изменённых значений (красный фон)

12.3. Колонка 3: Breakpoints

Панель управления точками останова.

Колонки таблицы:

  • Адрес — адрес точки останова
  • Условие — условие срабатывания (для условных BP)
  • Вкл — включена/выключена (✓/✗)
  • Сраб. — количество срабатываний

Кнопки:

  • + — добавить точку останова
  • 🔧 — редактировать условие (двойной клик по строке)
  • 🚫 — включить/выключить
  • ❌ — удалить выбранную
  • ✕ — очистить все
  • 💾 — сохранить пресет BP (JSON)
  • 📂 — загрузить пресет BP

12.4. Колонка 4: Регистры, Флаги, Стек, Статистика

  • Регистры — A, B, C, D, E, H, L, SP, PC, BC, DE, HL. Изменённые регистры подсвечиваются красным.
  • Флаги — S, Z, AC, P, CY. Установленные флаги подсвечиваются красным.
  • Стек — верхние 8 значений стека. Вершина стека подсвечивается красным.
  • Статистика — количество тактов, состояние (Остановлен / Выполняется / Готов).

12.6. Условные точки останова

Условные точки останова позволяют останавливать выполнение при выполнении условия.

Доступные переменные:

  • Регистры: A, B, C, D, E, H, L, BC, DE, HL, SP, PC
  • Флаги: S, Z, AC, P, CY
  • Память: mem[0x0100]
  • IO-порты: io[0x01]
  • Такты: cycles
  • Операторы: ==, !=, <, >, <=, >=, and, or, not

Примеры условий:

A == 0x55 — остановка когда A станет 0x55
HL > 0x1000 — когда HL превысит 0x1000
mem[0x0100] == 0xFF — когда ячейка памяти станет FF
Z == 1 — когда флаг Zero установлен
cycles > 10000 — после 10000 тактов
HL > 0x1000 and Z == 0 — комбинация условий

13. Вкладка «Трассировка»

Вкладка трассировки отображает историю выполнения инструкций.

13.1. Панель управления

  • 🔥 Включить запись — включение записи трассировки (чекбокс также на вкладке «Эмулятор»)
  • 🗑 Очистить — очистка буфера трассировки
  • 💾 Экспорт — экспорт трассировки (TXT / CSV / JSON)
  • Глубина — максимальное количество записей (по умолчанию 10000)
  • Записей: X / Y — текущее количество записей / максимальное

13.2. Поиск

Поле поиска поддерживает:

  • Адрес (HEX) — например, 0010 — поиск по адресу PC
  • Регистр OP значение — например, A==55, HL>1000, SP<=F000, Z=1
  • Мнемоника — например, CPI, JMP — поиск по мнемонике

Операторы сравнения: =, ==, !=, >, <, >=, <=

Кнопки:

  • 🔍 — выполнить поиск
  • ❌ — сбросить фильтр

15. MCP-интеграция

Программа включает встроенный MCP-сервер для интеграции с AI-ассистентами (Claude, Cursor, VS Code и др.).

Включение MCP-сервера

  1. Вкладка «Управление»
  2. Нажмите кнопку «MCP Server: OFF» — она переключится на «MCP Server: ON»
  3. Сервер доступен по адресу http://127.0.0.1:8000/sse

Конфигурация для Claude Desktop

{
"mcpServers": {
"i8080-ci": {
"url": "http://127.0.0.1:8000/sse"
}
}
}

16. Типовые сценарии работы

16.1. Загрузка и дизассемблирование прошивки

  1. Вкладка «Управление» → «Загрузить прошивку» → выберите .hex/.bin файл
  2. Вкладка «Дизассемблер» → «Дизассемблировать»
  3. Изучите код, используя стрелки переходов и цветовую подсветку

16.2. Отладка программы в эмуляторе

  1. Загрузите прошивку
  2. Вкладка «Эмулятор»
  3. Установите точки останова (двойной клик по строке кода)
  4. Нажмите F5 для запуска или F11 для пошагового выполнения
  5. Наблюдайте за регистрами, флагами и стеком
  6. Используйте Watch-окно для наблюдения за памятью

16.3. Условная отладка

  1. Установите точку останова
  2. Двойной клик по точке останова → введите условие
  3. Запустите выполнение — выполнение остановится только при выполнении условия

16.4. Анализ с трассировкой

  1. Вкладка «Эмулятор» → включите чекбокс «Трассировка»
  2. Выполните программу (F5) или пошагово (F11)
  3. Вкладка «Трассировка» — изучите историю выполнения
  4. Используйте поиск для фильтрации
  5. Экспортируйте трассировку для дальнейшего анализа

16.5. Работа с реальным устройством

  1. Подключитесь к устройству (COM-порт)
  2. Захватите шину (Ctrl+H)
  3. Читайте/записывайте память и IO-порты
  4. Освободите шину (Ctrl+U)

16.6. Тестирование памяти устройства

  1. Подключитесь к устройству и захватите шину
  2. Вкладка «Тест Памяти»
  3. Укажите диапазон и паттерн
  4. Запустите тест
  5. Изучите результаты в журнале

16.7. Сравнение образов

  1. Загрузите текущий образ (или подключитесь к устройству и прочитайте память)
  2. Вкладка «Сравнение» → «Загрузить файл для сравнения»
  3. Нажмите «Сравнить»
  4. Изучите различия в таблице

Приложения

A. Поддерживаемые инструкции i8080

Эмулятор поддерживает все 256 инструкций i8080, включая недокументированные:

  • NOP* (08, 10, 18, 20, 28, 30, 38, DD, ED, FD)
  • RET* (D9)
  • CALL* (CB)

B. Протокол связи с устройством

Программа использует протокол SLIP через COM-порт:

  • Скорость: 9600, 38400, 57600, 115200
  • Команды: NOP, HOLD, UNHOLD, чтение/запись памяти, чтение/запись IO

C. Форматы файлов

  • Intel HEX (.hex) — стандартный формат для прошивок
  • Binary (.bin) — двоичный формат (с указанием базового адреса при загрузке)

D. Форматы пресетов

  • Watch-пресеты — JSON (watch_preset.json)
  • BP-пресеты — JSON (bp_preset.json)
